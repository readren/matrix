# Cluster Binary Serialization & Macro Derivation

The cluster binary serialization subsystem (`readren.nexus.cluster.serialization`) provides deterministic, low-allocation binary encoding and decoding for network protocol messages, consensus payloads, and general data structures. See [Cluster Binary Serialization Developer Guide](cluster-serialization-guide.md) for concrete code examples and synthesized expansions, [Multi-Raft System Architecture](system-architecture.md) for the broader cluster transport context, and [Coding Guidelines](coding-guidelines.md) for repository-wide conventions.

## 1. Core Contracts & Invariance

- **Invariant Type Classes (`Serializer[A]` and `Deserializer[A]`)**: Both `Serializer[A]` and `Deserializer[A]` are invariant in `A`. Invariance prevents implicit ambiguity between a sum type and its subtype variants and ensures that discriminator headers are emitted and consumed strictly at the intended sum-type boundary rather than silently widening a product subtype to its parent sum serializer.
- **Variable-Length Quantity (VLQ) Framing & Reference Deduplication**: Primitive lengths and sum-type discriminators are encoded as unsigned variable-length quantities (VLQ). Object graphs that opt into reference tracking via `Writer.write` and `Reader.read` deduplicate repeated object identities within a composite message using back-reference headers (`0x40`), escaping leading content bytes that coincide with the back-reference header. Back-reference indices are serialized using signed VLQ (`putIntVlq` / `readIntVlq`) because signed VLQ encoding guarantees that the leading byte never equals `0x40`, precluding collisions with the back-reference escape header. Reference tables operate with 0-based indexing and strictly bypass primitive and value types via `ValueOrReferenceTest`, preventing boxing allocations and index desynchronization across write and read paths.

## 2. Direct Reflection Type Classification

Compile-time derivation (`Serializer.derive` and `Deserializer.derive`) inspects target types directly through compiler reflection rather than relying on `scala.deriving.Mirror`. Bypassing `Mirror` removes the compiler limitation that prevents `Mirror.SumOf` synthesis for parameterized sum types whose variants do not share identical type parameter lists (such as singleton `enum` cases extending `F[Nothing]` or variants that fix, permute, or subset parent type parameters) and extends derivation beyond algebraic data types.

Every target type is classified into one of five structural categories:

1. **Singleton**: A companion object, `case object`, or parameterless `enum` case. Serialization is a no-op; deserialization returns the singleton reference directly.
2. **Sealed Sum**: A sealed trait, sealed abstract class, or `enum` type, whether monomorphic or parameterized, possessing a non-empty set of child variants.
3. **AnyVal Value Class**: A concrete class extending `scala.AnyVal` with a single public parameter. In standalone derivation (`Serializer.derive` / `Deserializer.derive`), codecs are synthesized by delegating to the underlying type codec. In product field traversal, explicit in-scope codecs take precedence; when absent, the derivation pipeline transparently decomposes the value class, directly reading or writing the underlying primitive or reference value to eliminate JVM heap boxing and intermediary wrapper allocations.
4. **Opaque Type Alias**: A Scala 3 `opaque type` alias. Supported for explicit top-level derivation (`Serializer.derive` and `Deserializer.derive`) by resolving the underlying translucent type representation. Transitive field traversal strictly enforces type opacity: automatic piercing during product field serialization is rejected to preserve domain encapsulation, requiring explicit in-scope codecs.
5. **Concrete Product**: Any concrete class with an accessible primary constructor. This encompasses standard `case class`es, classes with multiple parameter lists, and non-ADT concrete classes, provided every primary constructor parameter name is exposed on the class as an accessible (non-private, non-protected) field or zero-argument getter method.

## 3. Parameterized Type & Child Variant Unification

- **Parameterized Product Construction**: When deriving a deserializer for an applied product type `P[A1, ..., An]`, constructor parameter types are substituted with the supplied type arguments `A1, ..., An`, ensuring that field deserializers are summoned for the specialized field types.
- **Child Variant Type Resolution in Parameterized Sums**: Given an applied sum type `S[A1, ..., An]` and a direct child variant `C`:
    - If `C` is a singleton, its variant type is the singleton term reference.
    - If `C` is a class with no type parameters, its variant type is the concrete type reference of `C`.
    - If `C` is a parameterized class with type parameters `T1, ..., Tm`, `C`'s base-type projection for `S` is structurally unified against `S[A1, ..., An]` to bind each `Ti`. If any `Ti` does not appear in `C`'s base projection of `S` (an existential or unconstrained child type parameter), derivation aborts at compile time with an explicit diagnostic.

## 4. Nested Sum Hierarchies & Diamond Inheritance Deduplication

Sum types that contain intermediate sealed sum subtypes support two dispatch topologies controlled by `NestedSumMatchMode`:

- **`FLAT` Mode (Default)**: Flattens nested sum types into a single-level pattern match (for serialization) and a single VLQ discriminator dispatch table (for deserialization), unless an explicit `given Serializer` / `Deserializer` for the intermediate sum type is in scope. When a variant inherits from multiple intermediate sum traits in a diamond hierarchy (for example, `LeadRequest extends Request, NonResponse`), flattened traversal deduplicates variants by type equality (`=:=`) so each leaf variant is assigned a single reachable branch and a single discriminator.
- **`TREE` Mode**: Preserves the hierarchy by emitting an outer discriminator for the intermediate sum type followed by a nested discriminator match for its children.
- **Intermediate Type-Class Boundary & Mode Decoupling**: If an explicit `given Serializer` / `Deserializer` exists for an intermediate sum trait, flattened traversal halts at that trait. The outer derivation treats the intermediate trait as an opaque variant requiring a discriminator in the outer criteria, while child variant serialization is delegated to the intermediate type-class instance, which may independently adopt a different `NestedSumMatchMode` and consult its own `DiscriminationCriteria`.

## 5. Explicit Field Givens & Self-Recursion Invariant

- **No Silent Auto-Derivation of Distinct Field Types**: Deriving a `Serializer[T]` or `Deserializer[T]` does not silently synthesize ad-hoc serializers for unrelated nested product or sum field types `F`; a `given Serializer[F]` / `Deserializer[F]` must exist in scope. This guarantees that sharing a field type across multiple messages reuses a single canonical serializer instance and respects any custom encoding or `DiscriminationCriteria` configured for `F`.
- **Direct and Indirect Self-Recursion**: Every derived `Serializer[T]` and `Deserializer[T]` binds a local `given self: Serializer[T] = this` (or `Deserializer[T] = this`) inside its `serialize` / `deserialize` method body:
    - **Direct recursion**: Product fields whose dealiased type equals the root derived type invoke `self` directly without performing an implicit search.
    - **Indirect recursion**: Container fields referencing the root type (such as `List[RoseTree[T]]` or `Option[Node[T]]`) resolve through standard container givens which summon the local `self` given, avoiding infinite compile-time macro expansion and runtime re-allocation.
    - **Value Class Wrapper Recursion**: When a product field wraps a recursive reference inside an `AnyVal` value class, the unboxed underlying type is checked against the root derived type, short-circuiting to `self` directly to prevent divergent implicit searches.

## 6. Match-Type `DiscriminationCriteria[-S]`

Custom discriminator assignments are specified by providing a `given DiscriminationCriteria[S]` in scope that overrides the upper-bounded type member `type Discriminator[P <: S] <: Int` with a Scala 3 match type mapping each variant subtype `P` to a non-negative integer literal constant.

- **Contravariance & Inheritance**: `DiscriminationCriteria[-S]` is contravariant in `S`. A single criteria defined for an outer sum type (or a wildcard parameterized sum type `Envelope[?]`) automatically satisfies searches for nested sum subtypes and concrete type instantiations unless overridden by a more specific `given` for the subtype.
- **Topology-Dependent Discrimination Invariants**: The structural elements requiring discriminators are dictated by `NestedSumMatchMode`: in `FLAT` mode without intermediate givens, intermediate sum traits are transparent and discriminators must be assigned only to leaf variants; in `TREE` mode, both intermediate sum traits and leaf variants require discriminators. When an intermediate sum has its own in-scope serializer/deserializer, the outer criteria must assign a discriminator to the intermediate trait itself.
- **Compile-Time Reduction**: The macro reduces the `Discriminator` match type for each variant to its integer literal constant. When a match type contains overlapping cases across an inheritance hierarchy, cases are evaluated in declaration order against the variant type.
- **Duplicate Discriminator Detection**: During deserializer derivation, all resolved discriminator constants within a dispatch table are checked for uniqueness at compile time; any collision aborts compilation with a diagnostic naming both conflicting variants.

## 7. Protocol Versioning & Product Schema Evolution

The serialization engine supports cross-version interoperability and product schema evolution without sacrificing invariant type class safety or requiring tagged protobuf-style framing overhead:

- **Monotonic Integer Versioning**: `ProtocolVersion` is represented as an opaque value type (`opaque type ProtocolVersion <: AnyVal = Int`) with monotonic linear ordering, encoded on the wire via Variable-Length Quantity (VLQ). A message version is compatible with an introduced feature if and only if the message version is greater than or equal to the feature's introduction version (`thisVersion >= otherVersion`).
- **Explicit Version Attribution (`@since`)**: Constructor parameters in product classes declare the protocol version in which they were introduced using the `@since(version: Int)` annotation. Parameters without `@since` belong to the baseline protocol version and are processed unconditionally.
- **Compile-Time Default Value Invariant**: Any product parameter annotated with `@since` must define a default constructor argument value. Derivation inspects the companion module at compile time for the corresponding default method; missing defaults abort compilation immediately to prevent runtime deserialization failure when communicating with older protocol versions.
- **Dynamic Wire Adaptation**: Serializers check the writer's governing version and suppress fields whose introduction version exceeds the target version, emitting only the subset recognized by older receivers. Deserializers inspect the reader's governing version: if the incoming message was produced by a version older than a field's introduction, the field is skipped on the wire and its default constructor argument value is substituted into the instance creation expression.
- **Strict Invariance Retention**: `Serializer[A]` and `Deserializer[A]` remain strictly invariant. Schema evolution occurs dynamically per message transmission via the reader and writer governing versions without runtime reflection or subtype widening.


## 8. Binary Payload Transfer & Buffer Lifecycle Invariants

- **Chunked Boundary-Aware Bulk Transfer Invariant**: Binary payload transfers across the serialization and channel layers partition transfers into contiguous chunks bounded by transport buffer capacity and frame boundaries. Writers and readers transfer payload memory using vectorized bulk copy operations rather than per-byte traversal, preserving framing headers and back-reference escape semantics.
- **Slice and Direct Buffer Streaming**: Serialization writers support direct sub-array slice and `ByteBuffer` streaming, transferring raw binary sources directly into transport buffers without allocating intermediate defensive heap arrays.
- **Transport Buffer Lifecycle Isolation & Heap Invariance**: Direct buffers managed by transport circular storage are ephemeral and recycled immediately upon message completion. Binary payloads intended for durable storage or consensus replication (such as state machine snapshot data) are copied into immutable heap structures (`IArray[Byte]`) across the transport boundary, preserving buffer lifecycle isolation and preventing native memory leaks from pinned direct buffers.
- **Primitive Scratchpad Isolation**: Framing-straddling primitive deserialization uses a minimal fixed-capacity scratch buffer sized strictly to the largest supported primitive, isolated from arbitrary-length payload deserialization.
- **Transport Buffer Capacity Ceiling Invariant**: `DualEndedCircularStorage` enforces a configurable ceiling (`maxBuffers`) on the number of backing buffers allocated per connection. When serialization or reception demands exceed this ceiling, `DualEndedCircularStorage` throws `StorageCapacityExceededException` to fail fast, preventing unbounded direct memory consumption. `Transmitter` captures this condition during serialization and translates it into `SerializationException`, causing any in-flight transmission to be aborted with a corrupted-package sentinel (`CORRUPTED_PACKAGE_SENTINEL_ENCODED`) without terminating the socket connection. `Receiver` detects capacity overflow during frame assembly and reports `ReceptionFailure`.
- **Quiescent Buffer Pruning Invariant**: `DualEndedCircularStorage` supports safe hysteresis-based buffer reclamation via `pruneTo(targetCount)`. Buffer deallocation is strictly forbidden during active transmission or unread packet processing (`readEndNode ne writeEndNode`). Pruning occurs only when the transport ring is quiescent (`readEndNode eq writeEndNode`), such as upon drain of the sequential transmission queue in `SequentialTransmitter.onIdleHandler` or following message dispatch in `Receiver.prepareStorageForNextCall`. Pruned nodes are unlinked from the ring, resetting the ring size to a minimal floor (by default 2 buffers) and releasing native direct memory to the garbage collector.

## 9. Object Reference Deduplication Lifecycle & Zero-Allocation Invariants

- **Connection-Bound Table Lifecycle**: Deduplication tables (`RecyclableIdentityIntMap` on the write path and `RecyclableObjectBuffer` on the read path) are bound 1:1 to the connection lifetime of `Transmitter` and `Receiver`, eliminating recurring table instantiation and heap garbage collection churn during message streaming.
- **Zero-Allocation Open-Addressing Identity Mapping**: The writer deduplication table operates as an open-addressing, linear-probing map over parallel flat arrays (`Array[AnyRef]` for keys and primitive `Array[Int]` for reference identifiers). Keys are compared strictly by object identity (`eq`) and hashed using bit-scrambled identity hash codes. Inlined primitive operations eliminate boxing of integer values and closure allocations.
- **Composite Frame Persistence & In-Place Reset**: Deduplication tables accumulate object identities across all transport buffer frames comprising a composite message package. Tables are reset in-place between distinct messages: the writer zeroes its key array via `Arrays.fill` while preserving array capacity, and the reader zeroes only occupied indices `0 until size` to promptly release deserialized message graphs for garbage collection while retaining backing buffer allocations.
- **Thread Confinement & Lock-Free Invariance**: Transmitters and receivers enforce strictly sequential message processing per channel (`SequentialTransmitter` FIFO queuing on transmit, and sequential NIO2 completion dispatch on receive). As a result, reference deduplication tables operate with absolute thread confinement, requiring no locks, atomic variables, or memory synchronization overhead within the table implementation.

## 10. Scala 3 Tuple Serialization & Composite Resolution Invariants

- **Inductive Structural Product Decomposition**: Tuples in Scala 3 are treated as first-class anonymous product types rather than nominal algebraic data types. Binary serialization and deserialization are implemented inductively in `CommonSerializers` using base cases for `EmptyTuple` and recursive steps for `*:[H, T <: Tuple]`. Standard tuple syntax `(T1, T2, ..., Tn)` desugars directly into `T1 *: T2 *: ... *: Tn *: EmptyTuple`, guaranteeing uniform support across arbitrary arities ($N \ge 0$) without the 22-element reflection ceiling of `Tuple22` or `TupleXXL`.
- **Zero-Discriminator Wire Parity**: Product tuples emit zero tag, discriminator, or length-header bytes on the wire. `EmptyTuple` produces and consumes exactly 0 bytes. Each element payload is written sequentially in declaration order matching product case class layout.
- **Strict Declaration-Order Deserialization Invariant**: In Scala, the cons operator `*:` is right-associative (methods ending with a colon bind to the right-hand operand). Direct expression chaining (`dH.deserialize(reader) *: dT.deserialize(reader)`) evaluates the tail receiver before the head argument, inverting stream read order. Deserializers must strictly evaluate `head` before `tail` using sequential value bindings before tuple construction to guarantee left-to-right stream consumption.
- **Transparent Composite & Macro Propagation**: Defining tuple typeclass instances in `CommonSerializers` allows macro-derived product types (`Serializer.derive[P]` and `Deserializer.derive[P]`) containing tuple fields to resolve field serializers automatically via standard implicit search, eliminating nominal wrapper boilerplate around composite tuple parameters.

## 11. Adversarial Payload Defense & Allocation Guard Invariants

- **Aggregate Transport Capacity Invariant**: Channel configurations (`Receiver` and `ParticipantService.DelegateConfig`) actively validate at construction time that aggregate circular storage capacity (`maxBuffers * buffersCapacity`) does not exceed `Int.MaxValue`, guaranteeing that the receiver's physical storage envelope is mathematically bounded within signed 32-bit integer space.
- **Pre-Allocation Remaining Content Bound Invariant**: Variable-Length Quantity (VLQ) length headers for arrays, strings, and collections must be validated against available transport bytes before backing memory or collection builders are allocated. In frame-based reception (`Receiver`), frame lengths are validated against `totalBufferCapacity` during packet ingestion (rejecting impossible lengths $> \text{totalBufferCapacity}$ as tainted sentinels), and total package content bytes are accumulated into an `Int` accumulator. This accumulated size is provided to the deserializer reader as an exact $O(1)$ 32-bit content ceiling (`remainingContentBytes: Int`). Requests requesting capacity exceeding remaining content bytes fail fast in $O(1)$ time with zero heap allocation.
- **Defensive Allocation Ceiling Invariant**: Deserializers enforce configurable maximum allocation thresholds (`AllocationLimits.maxAllocationBytes` and `AllocationLimits.maxCollectionElements`) regardless of available wire bytes. This prevents out-of-memory denial-of-service conditions when processing zero-wire-footprint types (such as singletons or `Unit`) or large single-frame allocations.
- **Structured Non-Fatal Fault Invariant**: Length violations, negative count headers, invalid reference keys, and unknown sum-type discriminators throw explicit subclasses of `DeserializationException` (`PayloadCorruptedException`). Because these exceptions derive from `RuntimeException`, they are caught cleanly by `scala.util.control.NonFatal` in transport reception handlers and translated into channel faults (`Fault`) rather than fatal virtual machine errors (`OutOfMemoryError`), allowing graceful socket teardown or channel restart without terminating the host actor or JVM process.
- **Synthesized Sum Discriminator Fallback Invariant**: Macro-derived sum-type deserializers synthesize an exhaustive fallback branch that intercepts unrecognized discriminator tags and raises `InvalidDiscriminatorException` with the target sum-type identifier and stream position, preventing raw pattern match failures from escaping the deserialization boundary.
